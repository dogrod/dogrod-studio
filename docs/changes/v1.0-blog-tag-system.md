# v1.0 Blog & Tag System Release

**Date**: 2024-12-18  
**Status**: Complete

---

## Overview

This release introduces a complete **Blog Management System** with multi-language support and a centralized **Tag Management System** for dogrod-studio. The implementation follows the established patterns from the Gallery module while introducing several UX improvements focused on content creation workflows.

---

## 1. Architecture & Database

### 1.1 Internationalization (i18n) Schema

Posts support multiple languages through a translation grouping pattern:

| Field | Type | Purpose |
|-------|------|---------|
| `language` | `'zh-CN' \| 'en-US'` | Post language identifier |
| `translation_group_id` | `uuid` | Links translations of the same content |

**Design Decision**: Rather than storing translations in a single row with JSON fields, each translation is a separate `posts` record. This allows:
- Independent publishing states per language
- Language-specific SEO metadata (slug, excerpt)
- Simpler queries without JSON parsing
- Future extensibility for additional languages

### 1.2 Tag System Architecture

#### Centralized Tags Table
```sql
public.tags (
  id, name, slug, description, color,
  created_by, created_at, updated_by, updated_at
)
```

#### Secure Statistics View
```sql
public.tag_stats (security_invoker = true)
  → Provides photo_count, post_count per tag
  → Respects RLS policies automatically
```

#### Junction Tables with Audit Fields
Both `photo_tag` and `post_tag` include full audit trails:
- `created_by` / `updated_by` → User accountability
- `created_at` / `updated_at` → Timestamp tracking (managed by DB triggers)

**Design Decision**: Using `security_invoker = true` on the view ensures that all queries through the view respect the calling user's RLS policies, preventing privilege escalation.

## 2. Blog Management (Studio)

### 2.1 Matrix List View

**Problem**: A flat post list becomes cluttered with multi-language content (2 rows for one article).

**Solution**: Posts are grouped by `translation_group_id` into a "Matrix View":

```
┌─────────────────────────────────────────────────────────┐
│ Cover │ Title           │ Translations │ Published     │
├─────────────────────────────────────────────────────────┤
│ [img] │ My Article      │ [ZH] [EN]    │ Dec 18, 2024  │
│ [img] │ Another Post    │ [ZH] [+EN]   │ Dec 17, 2024  │
└─────────────────────────────────────────────────────────┘
```

**Translation Badges**:
- **Solid badge** (ZH/EN): Translation exists → Click to edit
- **Dashed badge** (+EN): Translation missing → Click to create
- **Color coding**: Green = Published, Amber = Draft, Gray = Archived

**Implementation**: Client-side transformation using `useMemo` groups posts by `translation_group_id`. Primary post selection prefers `zh-CN`, then `en-US`, then first available.

### 2.2 Split-View Editor

**Problem**: The original 3-column layout (Editor | Preview | Metadata) was cluttered and detracted from the writing experience.

**Solution**: A clean 2-column split view focused on writing:

```
┌──────────────────────────────────────────────────────────────┐
│ [←] [Title...                        ] [🔲] [⚙️] [Save]      │
├─────────────────────────────┬────────────────────────────────┤
│ [B][I][Link][H2][H3][...]   │ Preview                        │
│                             │                                │
│ # My Post                   │ My Post                        │
│                             │ ═══════                        │
│ Write markdown here...      │ Write markdown here...         │
│                             │                                │
└─────────────────────────────┴────────────────────────────────┘
```

**Key Features**:
- **Left Pane**: Monospace textarea with formatting toolbar
- **Right Pane**: Live preview with Tailwind Typography (`prose` classes)
- **Mobile**: Tab-based interface (Write | Preview)
- **Zen Mode**: Full-screen focus mode (hides all chrome)

### 2.3 Drawer-Based Settings

**Problem**: Metadata controls (slug, cover, status, tags, translations) cluttered the main editor interface.

**Solution**: All "low-frequency" settings moved to a slide-out `Sheet`:

```
┌─────────────────────────────────┐
│ Post Settings              [×] │
├─────────────────────────────────┤
│ GENERAL                         │
│ Status: [Draft ▾]              │
│ Visibility: [Public ▾]         │
├─────────────────────────────────┤
│ IDENTIFICATION                  │
│ Slug: [my-post-title]          │
│ Excerpt: [...]                 │
├─────────────────────────────────┤
│ ORGANIZATION                    │
│ Tags: [Tag Combobox...]        │
├─────────────────────────────────┤
│ COVER IMAGE                     │
│ [Image Selector]               │
├─────────────────────────────────┤
│ TRANSLATIONS                    │
│ Current: 中文                   │
│ [English - Edit]               │
│ [+ Add Translation]            │
└─────────────────────────────────┘
```

**Trigger**: Settings icon (⚙️) in the editor header.

### 2.4 Syntax Highlighting

The preview pane now supports code block highlighting using `react-syntax-highlighter`:

- **Theme**: VS Code Dark Plus (`vscDarkPlus`)
- **Languages**: Auto-detected from fenced code block language
- **Styling**: Rounded corners, dark background, consistent with dark mode

## 3. Tag Management

### 3.1 Central Tag Module (`/admin/tags`)

A dedicated interface for tag curation:

| Column | Description |
|--------|-------------|
| Name | Tag name with color badge |
| Slug | URL-friendly identifier |
| Usage | Photo count / Post count |
| Created | Creation timestamp |
| Actions | Edit / Delete |

**Features**:
- Create/Edit via side dialog
- 18 color presets (Tailwind palette)
- Auto-slug generation from name
- Usage statistics from `tag_stats` view

### 3.2 Smart Tag Input ("Notion-style")

A reusable combobox component (`TagInput.tsx`) for assigning tags:

```
┌─────────────────────────────────────────┐
│ [Photography ×] [Travel ×]              │
│ ─────────────────────────────────────── │
│ Type to search or create...             │
├─────────────────────────────────────────┤
│ ○ Architecture                          │
│ ○ Nature                                │
│ ─────────────────────────────────────── │
│ + Create "New Tag Name"                 │
└─────────────────────────────────────────┘
```

**Interaction**:
1. **Select existing**: Click or type to filter → Click to add
2. **Magic Create**: Type new name → "Create [name]" appears → Enter to create instantly
3. **Remove**: Click × on pill

**Server Integration**: Uses `quickCreateTagAction` for inline creation with full audit field compliance.

## 6. Key Decisions Summary

| Decision | Rationale |
|----------|-----------|
| Separate post records per language | Simpler queries, independent states, extensible |
| Matrix view with client-side grouping | No API changes needed, instant UI response |
| Settings in drawer | Focus on writing, reduce cognitive load |
| `security_invoker` on tag_stats | RLS compliance without custom policies |
| Inline tag creation | Reduce friction, Notion-like UX |
| VS Code theme for code blocks | Developer familiarity, high contrast |
